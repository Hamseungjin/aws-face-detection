## Session Authentication / HTTP 401 Follow-up

**Date:** 2026-08-10  
**Scope:** FastAPI session cookie authentication only (not AWS IAM)  
**Commit performed?** No

### Observed symptoms (pre-fix)

| Request | Result |
|---|---|
| `POST /api/login` | **200 OK** (`{"ok": true, "user": ...}`) |
| `GET /api/me` | **200 OK** (session-status endpoint; always 200) |
| `GET /api/config` | **401 Unauthorized** (`authentication required`) |
| `POST /api/detect-labels` | **401 Unauthorized** (`authentication required`) |

`/api/me` returning HTTP 200 does **not** mean the session is authenticated. When the cookie is missing, the body is `{"authenticated": false, "user": null}`.

This 401 path is raised by FastAPI `require_user()` **before** any AWS call. It is **not** `cloudformation:DescribeStackResource` AccessDenied.

### Authentication implementation (from code)

| Item | Value / behavior |
|---|---|
| Login route | `POST /api/login` validates `WEBUI_AUTH_USERNAME` + PBKDF2 hash via `auth.verify_password` |
| Session key | `request.session["user"] = username` (also sets `kiosk_rate_scope`) |
| Auth oracle | `_current_user(request)` → `request.session.get("user")` |
| Gate | `require_user(request)` → HTTP 401 `"authentication required"` if missing |
| Middleware | Starlette `SessionMiddleware` (signed cookie) |
| Cookie name | `webui_session` (`WEBUI_SESSION_COOKIE`) |
| Max-Age | `28800` (8h) |
| SameSite | `lax` (configurable via `WEBUI_SESSION_SAME_SITE`) |
| Secure / https_only | from `WEBUI_SESSION_HTTPS_ONLY` (default **false** for local HTTP) |
| Path | `/` |
| Domain | not set (host-only cookie) |
| HttpOnly | yes (always) |
| Frontend | `axios` `withCredentials: true`, relative `/api` (or `/proxy/<port>/api` under code-server) |

### Cookie / session configuration found

| Setting | Local `.env` / loaded value | Notes |
|---|---|---|
| `WEBUI_SESSION_HTTPS_ONLY` | exists → **false** | Required for plain HTTP |
| `WEBUI_SESSION_SECRET` | exists (non-empty) | Not printed |
| `WEBUI_AUTH_USERNAME` | exists (`admin`) | |
| `WEBUI_AUTH_PASSWORD_HASH` | exists (non-empty) | Not printed |
| `SESSION_SAME_SITE` | `lax` | |
| `.env` loaded by running app? | **Yes** when CWD is backend; **hardened** to load by absolute path next to `config.py` | |

Production EC2 (`webui-bootstrap.sh`) sets `WEBUI_SESSION_HTTPS_ONLY=true` for HTTPS. That must **not** be used for local `http://localhost` / `http://127.0.0.1`.

### Curl cookie-jar reproduction

Controlled credentials (not the operator password) were used against the same FastAPI code path. Values redacted.

**With `WEBUI_SESSION_HTTPS_ONLY=false` (local HTTP mode):**

```text
POST /api/login
  → 200 OK
  → Set-Cookie: webui_session=<redacted>; path=/; Max-Age=28800; httponly; samesite=lax
  → Secure=false, HttpOnly=true, SameSite=lax, Path=/, Domain=unset
  → cookie_present=true (cookie jar)

GET /api/me  (with jar)
  → 200 {"authenticated": true, "user": "<diag-user>"}

GET /api/detect-labels (with jar)
  → 200 {"enabled": false, "lastUpdateStatus": "Successful"}   # NOT 401

GET /api/config (with jar)
  → 503 {"detail": "config unavailable: AWS access denied"}   # NOT 401
  → proves FastAPI session auth passed; remaining issue is IAM

POST /api/capture-frame (with jar, minimal JPEG)
  → 200 {"ok": true, "captureId": "...", ...}   # NOT 401

GET /api/config without cookie
  → 401 authentication required
```

**Host mismatch (confirmed):**

```text
Login + cookie jar on http://127.0.0.1:8082
GET http://localhost:8082/api/me with same jar
  → {"authenticated": false, "user": null}
```

Cookies are host-scoped: `localhost` ≠ `127.0.0.1`.

**Secure-cookie failure mode (class A, reproduced with config only):**

When `WEBUI_SESSION_HTTPS_ONLY=true`, Set-Cookie includes `Secure`. Browsers on plain `http://localhost` will not store/send that cookie → login body 200 + protected 401. Curl is less strict than browsers for Secure cookies on HTTP; browser behavior is the production risk for local HTTP.

### Exact root cause

Protected routes return 401 when the signed session cookie is **missing or not sent**, so `request.session["user"]` is empty.

`POST /api/login` only proves credentials; the UI previously treated login JSON success as full authentication without confirming the browser kept the HttpOnly session cookie.

Concrete failure modes that produce exactly this symptom:

1. **Secure cookie on plain HTTP** (`WEBUI_SESSION_HTTPS_ONLY=true` while using `http://localhost` / `http://127.0.0.1`)
2. **Host mismatch** (login on `localhost`, API on `127.0.0.1`, or the reverse)
3. **Config not reloaded** after changing `.env` (session flags are fixed at process import/startup)

With correct local flags (`WEBUI_SESSION_HTTPS_ONLY=false`) and a consistent host, curl cookie-jar authentication succeeds and protected endpoints no longer return 401.

### Exact fix

1. **Do not weaken production Secure cookies globally.** Keep environment-aware `WEBUI_SESSION_HTTPS_ONLY` (false local HTTP, true deployed HTTPS).
2. **Load `web-ui/backend/.env` via absolute path** so session flags/secrets load even if uvicorn is not started from that directory.
3. **Log non-secret session cookie config at startup** (`https_only`, `same_site`, cookie name, max_age, whether secret/username configured).
4. **Frontend:** after `POST /api/login` 200, call `GET /api/me`; only if `authenticated=true` proceed; otherwise show a session-cookie error (localhost vs 127.0.0.1, HTTPS_ONLY, restart).
5. **Tests** lock cookie flags and auth flow (login → me → protected not 401; anon 401; Secure flag when HTTPS_ONLY=true).

## code-server Cookie Re-encoding Compatibility Fix

**Date:** 2026-08-10  
**Scope:** Application-side compatibility for code-server `/proxy/<port>` Cookie header re-encoding  
**Commit performed?** No  
**Depends on:** Confirmed root cause in `2026_08_10_proxy_session_cookie_diagnosis.md`

### Confirmed root cause (re-stated)

Direct FastAPI session authentication works. Through code-server `/proxy/8080/`, the proxy reconstructs the `Cookie` request header with `encodeURIComponent`-style percent-encoding.

| Transformation | Example |
|---|---|
| base64 padding | `=` → `%3D` |

Lifecycle:

1. FastAPI `Set-Cookie` → OK  
2. code-server forwards `Set-Cookie` → OK  
3. Browser stores `webui_session` → OK  
4. Browser sends `webui_session` → OK  
5. code-server receives it → OK  
6. **code-server reconstructs Cookie → VALUE MUTATED**  
7. FastAPI receives cookie **name** → OK  
8. `SessionMiddleware` signed-session decode → **FAIL**  
9. `request.session["user"]` missing → `/api/me` `authenticated=false`

Secure / SameSite / Domain / localhost vs 127.0.0.1 / AWS / CloudFormation / IAM are **not** the root cause of this proxy failure mode.

### Middleware architecture

```text
Browser request
    ↓
CodeServerSessionCookieCompatMiddleware   # outermost
    ↓
SessionMiddleware
    ↓
FastAPI routes
```

Starlette / FastAPI `add_middleware()` wraps so that **last-added is outermost** (runs first on the way in). Confirmed on Starlette 1.6.0:

| Order | Middleware | Role |
|---|---|---|
| 1 (outer) | `CodeServerSessionCookieCompatMiddleware` | normalize only app session cookie value |
| 2 (inner) | `SessionMiddleware` | sign/verify session |

Registration in `web-ui/backend/app.py`:

1. `app.add_middleware(SessionMiddleware, ...)`  (added first → inner)  
2. `app.add_middleware(CodeServerSessionCookieCompatMiddleware, session_cookie_name=config.SESSION_COOKIE)` (added last → outer)

### Normalization behavior

| Rule | Behavior |
|---|---|
| Scope | HTTP only; websocket/non-HTTP unchanged |
| Target cookie | `config.SESSION_COOKIE` only (default `webui_session`) |
| Action | `urllib.parse.unquote` on that cookie **value** exactly once |
| Other cookies | preserved segment-for-segment (`code-server-session`, etc.) |
| Direct access | no percent escapes → no-op |
| Double-encoded | one pass only (`%253D` → `%3D`, not `=`) |
| Security | SessionMiddleware signature validation remains authoritative |
| Logging | never logs Cookie header or session values; optional `proxy_cookie_normalized=true` at DEBUG |

| `web-ui/backend/session_cookie_compat.py` | **New** pure normalizer + ASGI middleware |

## Transaction-Bound Reference Face Retrieval

**Date:** 2026-08-11  
**Status:** Application implementation complete; live AWS E2E blocked (data stack absent)

### Architecture

```text
SQLite retrieval_code
    → transaction (STORED)
        → locker_id
        → reference_frame_id (FRAME-A correlation)
        → reference_face_s3_key (locker-references/<tx>/reference.jpg)

reference_face_s3_key  vs  exact targetFrameId=FRAME-B
    → facecompare (Rekognition CompareFaces)
    → similarity >= 90
    → server-authorized STORED → RETRIEVING → open locker
```

No global FaceId DB. No face embeddings. No code-only locker open.

### SQLite schema change

Safe migration (`ALTER TABLE` on existing DBs; no drop/recreate):

| Column | Purpose |
|---|---|
| `reference_frame_id` | Verified STORE live frame UUID |
| `reference_face_s3_key` | Durable private S3 object key |
| `reference_face_created_at` | Creation audit |
| `reference_face_deleted_at` | Post-retrieval cleanup audit |

`retrieval_code` UNIQUE + `(retrieval_code, status)` index preserved.

### STORE binding

1. Browser captures FRAME-A via `/api/capture-frame`.
2. `POST /api/kiosk/store/face-verify` (ID image + targetFrameId) → facecompare.
3. On match ≥ 90: session stores only `verified_store_frame_id` (no images).
4. `POST /api/kiosk/store/complete` requires that session frame; copies S3 object to
   `locker-references/<transaction_id>/reference.jpg` (idempotent); writes SQLite.
5. Client cannot supply an arbitrary unverified reference frame (`403 STORE_FACE_NOT_VERIFIED`).

### RETRIEVE flow (UX)

```text
찾기 → 8자리 코드 → 얼굴 촬영 → 본인 확인 → N번 보관함 열림 → 완료
```

- ID verification removed from RETRIEVE
- Manual locker number entry removed
- Threshold remains **90**

### Server-side enforcement

`POST /api/kiosk/retrieve/start` requires `retrievalCode` + `targetFrameId`.

Code-only start is rejected (`TARGET_FRAME_ID_REQUIRED`). Mismatch / not-ready /
missing reference leave status **STORED**. Only match transitions to **RETRIEVING**.

### facecompare extension

New optional mode (mutually exclusive with `imageBase64`):

- `referenceS3Bucket` + `referenceS3Key` + `targetFrameId`
- SourceImage = S3 reference; TargetImage = exact frame S3
- Legacy ID-bytes mode unchanged for operator tooling

### S3 lifecycle

Existing CFN expires only `frames/` and `logging/` prefixes.  
`locker-references/` is **not** expired by bucket lifecycle → durable beyond general
frame TTL. **No CloudFormation change required** for prefix exclusion.

Cleanup: after `RETRIEVED`, demo default deletes reference immediately
(`KIOSK_REFERENCE_DELETE_ON_RETRIEVE=true`, retention seconds `0`).  
No legal retention period was invented; config is explicit.
